# VibeMoney: инструкции агенту

VibeMoney — набор правил и шаблонов проверки бизнес-идей до разработки.

## Границы данных
- Публичная часть: README.md, agent-rules/, templates/, examples/ и этот файл.
- Все личные цели, идеи, исследования, интервью, решения, адреса репозиториев и реализации находятся только в workspace/. Этот каталог исключён из Git.
- Не добавляй личные материалы в публичные файлы, коммиты, задачи или PR. Не используй git add -f для workspace/.
- В examples/ допустимы только явно обозначенные вымышленные примеры.
- Не публикуй репозиторий и не меняй его видимость без указания пользователя.

## Маршрутизация
- При создании, оценке или пересмотре идеи сначала прочитай agent-rules/idea-validation.md и agent-rules/evidence.md. Используй templates/idea/idea.md и templates/idea/experiment.md.
- Прочитай workspace/strategy.md, если он существует. Если целей и ограничений нет, выясни критичные параметры; не придумывай их.
- При переходе к реализации сначала прочитай agent-rules/project-creation.md.
- Перед работой над конкретным продуктом прочитай его AGENTS.md и актуальную документацию, даже если задача открыта из корня VibeMoney. Связанный бизнес-контекст ищи по одинаковому идентификатору в workspace/discovery/.
- Не переходи от обсуждения идеи к разработке автоматически. Запиши основание перехода и учитывай уже полученное разрешение пользователя; не спрашивай повторно.
- Не изменяй чужие репозитории и не перезаписывай существующие файлы проекта при обновлении шаблонов.

## Работа с Git
- Перед Git-операциями проверь корень нужного репозитория через git rev-parse --show-toplevel.
- Вложенные продукты имеют собственные репозитории. Не добавляй их как submodule или в историю VibeMoney.
- Перед коммитом проверяй состав staged-файлов и отсутствие личных данных. Игнорирование не удаляет ранее отслеживаемые файлы и историю.
