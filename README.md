# VibeMoney

Рабочее пространство для проверки бизнес-идей: от предположений о проблеме до обоснованного решения о разработке.

## Устройство

- `AGENTS.md` — инструкции агенту и маршруты чтения.
- `agent-rules/` — методика проверки и создания самостоятельных продуктов.
- `templates/` — шаблоны карточек, экспериментов и инструкций продукта.
- `examples/` — вымышленные примеры.
- `workspace/` — локальные материалы пользователя, полностью исключённые из Git.

## Начало работы

1. Создайте `workspace/discovery/` и `workspace/projects/`: пустые локальные папки не появляются при клонировании.
2. Скопируйте `templates/strategy.md` в `workspace/strategy.md` и задайте цели и ограничения.
3. Выберите постоянный идентификатор идеи, например `report-helper`, и скопируйте `templates/idea/idea.md` в `workspace/discovery/report-helper/idea.md`.
4. Попросите агента проверить идею по правилам VibeMoney. Неизвестные сведения должны оставаться неизвестными до получения данных.
5. Записывайте эксперименты в папке идеи, используя `templates/idea/experiment.md`; исходные материалы храните в `evidence/` рядом с карточкой.
6. При принятии решения о реализации следуйте [правилам создания проекта](agent-rules/project-creation.md).

Пример запроса: «Проверь идею в workspace/discovery/report-helper/idea.md. Выдели самые опасные гипотезы и предложи дешёвую проверку первой из них».

## Независимые продукты

Реализация живёт в `workspace/projects/<id>/` со своим `.git`, `AGENTS.md` и документацией. Идея остаётся в `workspace/discovery/<id>/`. Общий публичный реестр репозиториев не ведётся. При необходимости адрес хранится в настройках Git самого продукта.

Клонирование VibeMoney не скачивает личные материалы и продукты. Для переноса на другой компьютер используйте отдельное приватное резервное копирование workspace и клонирование репозиториев продуктов. Gitignore не является резервной копией или защитой от чтения локальных файлов.

Продукт должен работать без родительского VibeMoney. Шаблоны копируются при создании и далее развиваются самостоятельно.

## Приватность и публикация

Перед коммитом проверяйте изменения. В публичной истории не должно быть реальных интервью, бизнес-данных, адресов частных продуктов и секретов. Добавление файла в `.gitignore` не очищает прежнюю историю.
